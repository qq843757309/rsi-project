# RSI 数据平台接入规范模板

版本 v0.1 建议稿。这里是元数据及事件信封，不是业务实验完整字段模型。所有示例均为虚构数据，hash 为占位值，任何 referenced policy、SLA、URI 或身份都没有实际创建。

## 文件

- asset.schema.json：统一资产版本登记信封，文件类要求原件位置和完整性信息。
- event.schema.json：CloudEvents 1.0 结构的业务及 Agent 运行事件，Agent 事件额外要求 Agent 版本与 Trace 映射。
- data-contract.schema.json：团队接入契约登记信封，结构化契约额外要求粒度、主键字段和字段语义。
- 四份 example.json：资产、业务事件、Agent 事件、结构化团队契约示例。

内网运行时把这些文件装入本地 Schema 注册表，外部 $schema URI 是规范标识，不需要访问外网。建议启用 Draft 2020-12 和 FormatChecker 等价配置。

## 必须由平台服务另行验证

1. 身份绑定及团队、项目读写授权。Schema 验证不能防止伪造身份。
2. 资产、版本、规则、策略和输入输出引用实际存在且可访问。
3. hash 与文件内容相同，真实 MIME、大小和文件安全检查通过。
4. 必填来源位置符合文件格式，页码、单元格、bbox 或音频时间段有效。
5. 版本发布门禁、质量状态、规则证据及人工确认符合契约。
6. event source/id 幂等、同键同内容重试、同键异内容冲突、乱序状态和任务终态对账。
7. 团队 extensions 的 Schema 登记和命名空间校验。当前核心模板仅约束扩展容器，领域约束由团队契约提供。
8. 单位、粒度、实验条件、关联口径与缺失语义业务有效。
9. 数据契约语义兼容性、服务配额、生命周期和恢复能力。
10. 敏感数据过滤、原件和索引授权，以及撤权后的缓存、记忆和下载拒绝。

本地检查已验证 3 个 Schema 合法、4 个正向示例通过，以及 11 个缺字段、无原件位置、非法 hash、无 Agent 引用、未知核心字段和日期错误的反向样例被拒绝。该检查不等同于生产 API 准入或权限验证。

# RSI 自进化 Agent 数据平台：10 模块详细建设方案 v2.0

日期：2026-10-03。面向宁德时代香港研究院内部架构决策。

## 1. 建设边界与现状

一期包含实验填报和自然语言统一查询结构化实验数据及文档，不承担科学推理。约 50 名用户；OceanBase MySQL 兼容，有约 3000 张独立明细表和少量挂测总表；Excel/共享盘已有入库脚本，实验接口和知识库已有雏形。原件、文档元数据和专家经验管理待补齐。内网已有 LLM、embedding 与公司 AD，部署均在内网。

挂测总表是实验员针对一批电芯完成实验后填入的汇总结果。不能直接假设它与明细存在固定平均、最大值或其他计算关系，需登记人工口径及关联键。

以下方案是项目建议，公开来源说明能力模式，不代表对 OceanBase 的即插即用兼容性、采购许可或研发收益承诺。未知版本、文件体量、活跃并发与接口能力均作为实施核查项，不以虚构参数定容量。

## 2. 总体架构

交互层：填报、统一查询、反馈与评测。服务层：统一 API、AD 认证与业务授权、查询编排。业务层：接入、目录语义、专家知识。加工层：原件元数据、解析质量、benchmark。基础层：OceanBase、内网原件存储、全文/向量索引、模型服务、任务和版本管理。

业务数据平面保管实验、文档和确认知识；进化数据平面保管可见调用、结果、反馈、评测及配置快照。通过 API、元数据目录和事件记录三层联接。代码和权重进化后续才新增训练快照、制品、沙箱和发布门禁。

## M01. 数据接入与实验填报

**目标：** 把人工填报、Excel 脚本和共享盘接入统一为可追踪的提交过程。

**项目现状：** 已有 Excel 自动入 OceanBase 的脚本，以及实验录入接口雏形。

### 一期具体建设内容

1. **版本化填报模板：** 字段类型、必填项、单位、范围、实验标识与附件要求共同发布。模板升级保留旧版解释规则。

2. **交互与批量导入：** 草稿、提交、预检查和逐行错误定位。导入先展示校验结果，再执行获准的正式写入。

3. **标识与字段映射：** 统一项目、批次、电芯、实验和记录标识。旧 Excel 列名映射到标准字段，保存映射版本。

4. **幂等与事务写入：** 提交幂等键防重复，版本号识别并发修改。写入在受控事务中完成，模型无生产写入凭据。

5. **复核与修订状态：** 草稿、提交、复核、入库、退回或作废。科学异常可提示或复核，保存旧值和修订原因。

6. **接入任务管理：** 记录批次、源文件、处理数量和失败位置。失败可重试、暂停和续跑，重复执行不重复入库。

### 可选能力及触发条件

- **审批工作流：** 跨角色复核或复杂状态转换成为高频需求后引入工作流引擎，普通提交先用轻量状态机。
- **CDC / 仪器直连：** 明确数据实时性、仪器协议与稳定主键后建设；一期不因已有脚本就默认增加消息总线。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 自研模板＋现有脚本 | NOMAD 展示 Schema 驱动 ELN [S01]；本项目复用已验证录入逻辑。 | 字段治理和前端需要开发，脚本需补幂等与监控。 | 一期建议 |
| 接入现成 ELN / LIMS | 采用已有实验记录/样品流程，平台对接其 API 与数据模型。 | 产品、流程和接口需评估，不能假设公司已经存在。 | 已有系统成熟时复用 |
| 工作流＋事件接入 | DAG 调度管理依赖和批任务 [S18]，与实时事件消费者分别实现。 | 新增调度/消息基础设施，运维与权限更复杂。 | 任务规模驱动 |

**推荐：** 自研字段与提交薄层，复用既有脚本和录入接口。优先治理批次/电芯/实验标识，审批复杂度按真实业务决定。

### 数据流、记录与验收

选择模板与批次 → 保存草稿或上传 → 校验字段与权限 → 复核 / 确认提交 → 事务写入与防重 → 发布记录及反馈。

输入：填报模板、Excel 文件、附件、用户与项目身份。

输出：正式实验记录、导入报告、提交状态、源文件和版本关联。

关键字段：submission_id、template_version、batch_id、cell_id、experiment_id、idempotency_key、revision。

- 重复提交不重复入库，并发修改能提示冲突。
- 错误能定位到字段/行，修订能追溯旧值。
- 同一字段从页面或脚本入库采用相同单位与标识。

参考：[S01 NOMAD ELN](https://docs.nomad-lab.eu/howto/manage/gui/eln.html)；[S18 Airflow Architecture](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/overview.html)。

## M02. 原始文件与元数据管理

**目标：** 将共享盘文件登记为带版本、归属、权限和来源的原始资产。

**项目现状：** PPT、PDF 与专家资料留在科研共享盘，统一资产管理待建。

### 一期具体建设内容

1. **原件登记与完整性：** 每个文件生成 asset_id 和校验值，保留来源路径、采集时间及原始文件，不用解析文本替代原件。

2. **文件版本与去重：** 内容相同可复用物理对象，但项目归属和权限分别管理。文档修改生成新版本，保留旧证据。

3. **元数据与归属：** 登记文档类型、项目、负责人、密级、主题、实验/批次关联、版本状态和存储引用。

4. **附件与可控下载：** 通过数据服务返回原件或授权下载。路径/链接不能绕过访问校验，访问记录关联用户身份。

5. **生命周期与撤回：** 区分有效、替代、撤回与归档。源数据撤回联动片段、索引和缓存，日志按保留规则处理。

6. **解析产物登记：** 文本、表格、图片描述与切分结果登记为派生资产，关联原文件版本和处理程序版本。

### 可选能力及触发条件

- **保留锁定与法律留存：** 有明确保留要求时评估 WORM 或 retention，提前明确谁可删除、保存多久。
- **迁移与分层归档：** 热冷数据成本或文件服务容量出现瓶颈时增加归档策略，资产标识保持不变。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 私有对象存储＋OceanBase | 对象版本和删除标记可参考 S3 接口语义 [S02]，元数据留在关系库。 | 新增存储服务与备份，S3 兼容不等于所有能力一致。 | 推荐评估 |
| 受管理文件服务＋目录 | 原件暂留内网文件服务，平台记录引用、校验值与版本副本。 | 改名、覆盖、直链权限需约束，历史版本需补齐。 | 一期可行备选 |
| 企业内容管理系统 | 统一文件生命周期、文档审批、版本和组织归属，再通过接口接入。 | 产品授权、插件、权限同步及系统归属需验证。 | 已有成熟系统时复用 |

**推荐：** 关系库保存元数据与权限，原件放私有资产存储；搜索索引作为可重建副本。对象存储品牌以公司政策和恢复测试决定。

### 数据流、记录与验收

扫描或受控上传 → 登记归属与权限 → 校验值与版本判定 → 持久化原件 → 登记派生产物 → 授权预览与下载。

输入：共享盘文档、上传附件、源权限与项目归属。

输出：可追踪原件、元数据目录、版本与派生资产关系。

关键字段：asset_id、version_id、checksum、source_uri、storage_ref、owner、classification、status。

- 返回的证据能定位原文件版本。
- 同内容跨项目去重不会合并权限。
- 撤回后搜索与下载均拒绝访问，旧证据仍按规则可审计。

参考：[S02 S3 Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html)；[S20 AiiDA](https://arxiv.org/abs/2003.12476)。

## M03. 数据目录与业务语义

**目标：** 让自然语言查询在约 3000 张独立表中选对来源、字段、关联和统计口径。

**项目现状：** OceanBase 已有约 3000 张独立实验明细表及少量人工填报的挂测总表。

### 一期具体建设内容

1. **技术元数据采集：** 采集表、列、类型、主键、更新频率和结构变化。采集账号只读，扫描不影响生产负载。

2. **业务主题与负责人：** 按实验类型与项目组织数据域，登记用途、负责人、完整度、权限和可用状态。

3. **术语与指标定义：** 维护同义词、单位、时间含义、指标公式及排除规则，区分批次汇总与单电芯明细。

4. **关联与批准视图：** 明确批次、电芯、实验和文档的关联键，发布获准连接与只读视图，避免模型猜测 JOIN。

5. **Schema 检索与压缩：** 先授权过滤，再主题/关键词/语义召回、候选重排，只提供必要表与字段给模型。

6. **目录版本与发布：** 字段解释、映射、指标、视图都保存版本。Schema 变化触发索引更新和查询回归。

### 可选能力及触发条件

- **完整 Catalog 产品：** 跨团队 owner、血缘、治理和搜索成为主要工作后评估 OpenMetadata 等产品，连接器需 PoC。
- **领域本体 / 知识图谱：** 需要跨材料实体多跳关系查询时引入，普通关联先由关系映射和语义模型完成。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| OceanBase 上轻量目录 | 自研 tables / columns / metrics / joins 注册表与发布流程。 | 表数多时仍需要业务负责人持续补释义。 | 一期建议 |
| OpenMetadata 类 Catalog | 官方数据契约覆盖 Schema、质量和语义 [S03]。 | 新增服务、索引与连接器运维，OceanBase 采集需核查。 | 公司级治理候选 |
| 指标语义层 / dbt 模式 | dbt 语义层统一指标与关联逻辑 [S04]，借鉴定义方式。 | 不默认产品支持 OceanBase 或满足全内网部署。 | 指标复杂时评估 |

**推荐：** 先对高频实验主题建立目录和批准视图，再覆盖长尾表。若存在一实验一表，渐进规范，避免一期全量迁移。

### 数据流、记录与验收

采集技术 Schema → 归类实验主题 → 补充字段与口径 → 确认关联与视图 → 授权检索候选表 → 发布并执行回归。

输入：数据库 Schema、历史 SQL、专家术语与业务统计定义。

输出：获准数据目录、语义条目、视图及候选 Schema。

关键字段：table_id、domain、owner、metric_id、grain、join_rule、schema_version、approved_view。

- 代表性问题能选中正确的数据域和表。
- 同义词、时间和单位按发布定义解释。
- 汇总与明细的统计粒度可解释，结构变化能发现。

参考：[S03 OpenMetadata Data Contracts](https://docs.open-metadata.org/v1.12.x/api-reference/data-contracts)；[S04 dbt Semantic Layer](https://docs.getdbt.com/docs/use-dbt-semantic-layer/dbt-sl)。

## M04. 数据处理与质量管理

**目标：** 把可解析、可关联和科学上可信的检查分开，产出可用数据及质量证据。

**项目现状：** 脚本已处理部分结构化数据，PPT/PDF 解析和统一质量流程待建。

### 一期具体建设内容

1. **结构化质量规则：** 校验类型、必填、范围、重复、单位、关联键和时间。规则按模板/数据域登记并版本化。

2. **多格式解析与 OCR：** 原生文本优先，扫描件按需 OCR。PPT、表格、页标题和图片说明分别保留结构。

3. **来源位置与切分：** 保留页、幻灯片、表格和单元格位置，按结构切分，必要时带相邻上下文与表头。

4. **科学上下文标准化：** 观测值带单位、方法、条件、时间和样品标识。原值与标准值并存，保留转换依据。

5. **实体匹配与复核：** 优先用稳定标识关联，别名匹配保留置信度和候选，不确定关联进入人工处理队列。

6. **质量结果与问题闭环：** 保存规则结果、解析异常、专家纠正与修复版本，重新处理后更新派生资产及索引。

### 可选能力及触发条件

- **多模态图像理解：** 当性能证据在图表或显微图片且文本不足时评估内网视觉模型，需独立标注评测。
- **质量产品 / 血缘采集：** 规则与接入任务大量增长时引入 GX / OpenLineage，科学规则仍由团队定义。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 本地解析器＋规则薄层 | Docling 统一结构并保留 provenance [S05]，结合专用 PPT/表格适配。 | 复杂图表、公式和合并表格必须用真实文档验证。 | 一期建议 PoC |
| GX 类质量框架 | Checkpoint 执行验证与后续动作 [S06]。 | 需要自定义科学规则与 OceanBase 数据适配。 | 规则规模较大时 |
| 内网多模态模型解析 | 对图表、扫描件或复杂版面使用视觉/语言模型辅助抽取。 | 推理成本与幻觉，必须绑定证据并进行抽样审核。 | 针对难文档增量 |

**推荐：** 先用分格式解析和轻量规则覆盖常见文档，难文档进入专门队列。质量规则记录“阻断/警告/需复核”级别。

### 数据流、记录与验收

选择解析与规则 → 提取结构与位置 → 标准化字段单位 → 执行规则与关联 → 隔离异常并复核 → 发布可用版本。

输入：原始文件、实验记录、规则/词典和已确认关联键。

输出：标准化数据、证据片段、质量报告及异常任务。

关键字段：parser_version、rule_version、page_no、table_ref、raw_value、normalized_value、confidence。

- 解析结果保留正确页位置和表头条件。
- 转换过程可复现，关键抽取字段通过标注核对。
- 错误不被静默标成可用，修复后可重建索引。

参考：[S05 DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/)；[S06 Great Expectations Checkpoints](https://docs.greatexpectations.io/docs/core/trigger_actions_based_on_results/create_a_checkpoint_with_actions/)；[S17 OpenLineage](https://openlineage.io/docs/spec/examples/)。

## M05. 自然语言统一查询

**目标：** 一个入口协同结构化查询与文档检索，结果带口径、版本和来源证据。

**项目现状：** 一期已明确自然语言查询需求，内网有可用 LLM 和 embedding。

### 一期具体建设内容

1. **意图与条件澄清：** 区分结构化、文档和混合查询，识别时间、批次、实验、指标；歧义影响结果时追问。

2. **授权 Schema 选择：** 先过滤权限，再检索相关表/字段/关联，携带批准语义和视图，控制上下文体积。

3. **SQL 生成与静态校验：** AST 检查仅允许获准查询，限制语句类型、表、列、函数、关联及多语句；不只查字符串。

4. **受限只读执行：** 只读身份与服务端行/列策略控制执行，限制行数、耗时、导出和资源，错误有限次修正。

5. **全文与语义检索：** 关键词匹配编号和专业术语，向量召回语义相近内容，过滤有效版本并按需重排。

6. **结果整合与反馈：** 分别展示明细、汇总和文档证据，摘要只基于已授权结果，保存 query_id、版本与纠正。

### 可选能力及触发条件

- **多轮查询 / 可视化分析：** 在单轮正确性稳定后追加上下文管理和图表，缓存按用户、项目和权限版本隔离。
- **GraphRAG / 图文检索：** 普通混合检索无法回答已定义的关系或图像任务时评估，不默认引入图库或视觉模型。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 受控 SQL＋统一检索服务 | SQLGlot 提供 AST 基础 [S07]；OpenSearch 提供混合检索 [S08]。 | 授权、语义正确性和结果合并需要自行实现。 | 一期建议 |
| 全文搜索＋独立向量服务 | Qdrant 支持混合查询组合 [S10]，可与现有全文能力融合。 | 双索引、融合排序、权限与版本一致性需维护。 | 向量负载明确时 |
| PostgreSQL＋pgvector | pgvector 是 PostgreSQL 扩展 [S11]，适合已有 PG 环境组合检索。 | 本项目是 OceanBase，采用该路线要新增 PG，非零成本。 | 有 PG 治理基础时 |

**推荐：** 采用受控 SQL 与文档混合检索两条路径，统一授权和结果出口。优先验证选表正确性、统计粒度及引用准确性。

### 数据流、记录与验收

认证与意图识别 → 选表 / 文档召回 → SQL 与权限校验 → 只读执行 / 重排 → 结果对齐与摘要 → 引用展示与反馈。

输入：问题、用户/项目、批准目录、实验视图和文档索引。

输出：结构化结果、文档证据、查询口径、可追踪解释与反馈。

关键字段：query_id、intent、schema_refs、sql_hash、evidence_refs、model_version、policy_version。

- SQL 正确性用结果核对，不以执行成功替代。
- 专业名、时间、批次和汇总口径正确。
- 越权/无证据/冲突/空结果均有明确行为。

参考：[S07 SQLGlot](https://github.com/tobymao/sqlglot)；[S08 OpenSearch Hybrid Search](https://docs.opensearch.org/latest/vector-search/ai-search/hybrid-search/index/)；[S09 OpenSearch DLS](https://docs.opensearch.org/latest/security/access-control/document-level-security/)；[S10 Qdrant Hybrid Queries](https://qdrant.tech/documentation/search/hybrid-queries/)；[S11 pgvector](https://github.com/pgvector/pgvector)。

## M06. 专家经验与知识管理

**目标：** 把专家经验沉淀为带条件、证据、反例和责任人的可复用知识。

**项目现状：** 计划通过专家访谈形成 benchmark，经验管理需要同步建设。

### 一期具体建设内容

1. **案例化访谈采集：** 围绕一次真实判断采集问题、备选方案、条件、决策理由和结果，保存原始访谈记录。

2. **经验卡结构化：** 标题、适用条件、动作、理由、禁用条件、支持证据与反例，关联项目/实验/来源位置。

3. **证据类型与审核：** 区分实验事实、专家启发、文献结论、仿真预测和 Agent 猜测，专家确认后发布。

4. **分歧与冲突管理：** 不同专家意见并存，展示条件与证据差异；冲突进入复核，不用自动摘要合并为事实。

5. **检索与使用反馈：** 按材料/实验范围检索已批准经验，记录被何任务引用、专家是否接受、后续结果如何。

6. **生命周期与知识版本：** 候选、批准、争议、替代、失效与归档状态，引用保留版本，适用条件变化后复核。

### 可选能力及触发条件

- **自动经验蒸馏：** 有足够高质量成败记录时生成候选经验。自动抽取不直接发布成科学事实。
- **时态图谱 / 技能库：** 需要跨时间关系推理或可执行经验时分别评估图谱、Git 技能与沙箱验证。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 关系表＋搜索索引 | 结构化经验卡在 OceanBase，描述检索复用全文/向量索引。 | 字段与专家审核需自研，运维增量较少。 | 一期建议 |
| 反馈驱动记忆方案 | Reflexion 展示反馈反思与情景记忆 [S12]。 | 来自通用任务研究，化学经验仍需外部证据与专家确认。 | 二期候选蒸馏 |
| 知识图谱＋技能版本库 | 图表达多跳关系，技能代码进入 Git/制品，描述做语义索引。 | 图谱抽取、冲突与代码执行成本，需独立治理。 | 关系/技能需求驱动 |

**推荐：** 一期先做经验卡和审核工作台，与 benchmark 同源分流。后续蒸馏候选需要验证，不能用记忆数量代表科研价值。

### 数据流、记录与验收

访谈或反馈采集 → 生成经验候选 → 关联证据与反例 → 专家复核与修订 → 发布授权经验 → 使用反馈和再复核。

输入：访谈、历史报告、实验案例、专家修正及任务反馈。

输出：已审核经验卡、适用条件、证据、分歧和使用记录。

关键字段：experience_id、applies_when、evidence_type、source_refs、reviewer、status、supersedes。

- 每条批准经验有来源和适用条件。
- 冲突意见能找到各自证据，不被静默覆盖。
- 过期经验能撤回，历史引用仍能定位版本。

参考：[S12 Reflexion](https://arxiv.org/abs/2303.11366)；[S01 NOMAD ELN](https://docs.nomad-lab.eu/howto/manage/gui/eln.html)。

## M07. Benchmark 与反馈评测

**目标：** 建立独立、可重复的查询标尺，支撑版本改进与后续进化。

**项目现状：** 专家将通过访谈构建 benchmark，尚需定义题型、标注和评分流程。

### 一期具体建设内容

1. **任务分类与采样：** 覆盖选表、条件、聚合、关联、文档、混合查询、拒绝和异常，按真实使用分布采样。

2. **标注与评分准则：** 保存预期结果、证据位置、容差、统计口径与评分维度，分歧标注由专家校准。

3. **快照与集合隔离：** 训练/开发/测试分别管理，同实验近重复案例关联去重，隐藏答案与评分规则不进入检索。

4. **自动与人工评分：** SQL 结果比对、引用定位、权限拒绝用规则；摘要等开放题专家为主，LLM 评分作辅助。

5. **版本对比与回归：** 锁定数据、语义、索引、模型和提示词版本，记录逐题结果、多次运行波动及能力退化。

6. **反馈与失败证据策展：** 用户纠正绑定 query_id，失败分型后进入开发集或回归集，测试集保持独立刷新机制。

### 可选能力及触发条件

- **上线门禁 / 在线抽样：** 有稳定基线后定义变更门禁与在线质量监测，抽样比例依据成本和风险确定。
- **实验收益评测：** 后续科研推理用真实实验数、周期和候选质量评测，不能借查询 benchmark 宣称材料发现提升。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 轻量 benchmark 管理 | 表/文件保存任务快照，自研执行器与结果比对，专家审核。 | 需要维护用例、版本和报告，结构简单。 | 一期最小方案 |
| MLflow 评测工作流 | 官方支持评测数据集和历史运行记录关联 [S13]。 | 自部署能力、模型评估器和内部数据权限需核查。 | 可优先 PoC |
| Langfuse 数据集与观测 | 官方支持自托管的观测及评测相关能力 [S14]。 | 涉及多存储组件和可选授权功能，不能当轻量单服务。 | 统一观测需要时 |

**推荐：** 先建设查询 benchmark。优先结果比对与证据定位，专家参与校准。MLflow / Langfuse 经 PoC 后选一种主平台，避免重复维护。

### 数据流、记录与验收

真实任务采样 → 专家标注与校准 → 冻结集合和快照 → 运行候选与基线 → 逐题评分和归因 → 批准发布或修订。

输入：专家问题、预期结果、证据、真实查询及用户纠正。

输出：冻结数据集、逐题评分、版本差异、失败批次与发布依据。

关键字段：case_id、dataset_snapshot、expected_result、rubric_version、run_id、score_dimensions。

- 测试答案不能通过在线检索获得。
- 逐题结果能回放到当时版本，失败有分型。
- 新版本比较覆盖旧能力，评分不只保留总分。

参考：[S13 MLflow Evaluation Datasets](https://mlflow.org/docs/latest/genai/datasets/)；[S14 Langfuse Self-hosting](https://langfuse.com/self-hosting)。

## M08. 身份权限与审计

**目标：** 将 AD 用户身份转换为覆盖查询、填报、原件与派生资产的数据访问策略。

**项目现状：** 公司 AD 登录可用，业务授权范围和服务账户现状待核查。

### 一期具体建设内容

1. **身份接入与会话：** 复用公司批准的 SSO/AD 接入，处理停用、组变更、会话过期和服务身份，不另建重复身份源。

2. **角色与项目授权：** 化学专家、实验员、数据管理员、平台管理员分工，叠加项目、数据域、密级与有效期。

3. **SQL 与字段访问：** 服务端执行表、列与必要的行过滤；只读身份限制查询，写入与审批采用独立权限。

4. **文档与派生权限：** 原件、片段、索引、摘要、预览和导出继承源权限，下载链接不能绕过鉴权。

5. **撤回与缓存失效：** 策略版本更新后先阻断访问，再同步索引与缓存；跨用户缓存必须含授权上下文。

6. **审计与运维访问：** 记录谁对什么资产做什么、依据哪个策略；审计日志本身受权限和保留期控制。

### 可选能力及触发条件

- **ABAC 策略引擎：** 跨组织密级、目的、位置等属性规则复杂后引入策略服务，简单项目权限先做稳定。
- **细粒度脱敏与审批：** 存在字段敏感度差异或受控导出时增加脱敏、访问申请和限时授权，按实际政策定义。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 公司 SSO＋应用授权 | 复用已有身份服务，平台管理角色、项目及数据策略。 | 需要明确 AD/SSO 协议与账号停用同步。 | 一期建议 |
| Keycloak 身份适配 | 官方支持 LDAP/AD 联邦 [S15]，可作为多个内网应用的身份桥接。 | 新增身份基础设施，不替代数据授权和审批。 | 现有 SSO 无合适接口时 |
| 搜索/数据库原生权限 | OpenSearch DLS 控制搜索/get 读结果 [S09]，与业务层联合防护。 | DLS 不限制写入，SQL、原件和缓存仍需独立授权。 | 作为防护能力组合 |

**推荐：** 统一身份入口、统一策略语义、各数据路径落实授权。AD、模型提示词或搜索 DLS 都不能单独承担全链路权限。

### 数据流、记录与验收

认证用户 / 服务 → 加载角色与项目 → 判定资源及动作 → 执行受限操作 → 返回前再检查 → 审计与撤回同步。

输入：AD 身份、角色、项目关系、数据分级和源权限。

输出：授权决策、受控结果/写入、审计与权限变更状态。

关键字段：principal_id、role、project_scope、asset_scope、action、policy_version、decision_id。

- 越权查询、原件下载、写入和缓存读取均拒绝。
- 停用/撤回后在约定时限内生效。
- 每次关键操作能追查身份、资产与策略依据。

参考：[S15 Keycloak AD / LDAP](https://www.keycloak.org/docs/26.8.0/server_admin/)；[S09 OpenSearch DLS](https://docs.opensearch.org/latest/security/access-control/document-level-security/)；[S16 MCP Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)。

## M09. 数据服务与 Agent 接口

**目标：** 用稳定业务接口连接页面、现有 RSI Agent 与底层数据，避免调用方直连各存储。

**项目现状：** 现有 Agent 已有实验录入与知识库雏形，接口需盘点和适配。

### 一期具体建设内容

1. **统一业务 API：** 目录、查询、填报、文档、任务、反馈、评测分别定义契约，避免一个入口隐藏全部业务语义。

2. **用户身份透传：** 网关认证服务与用户，调用下游携带获准范围，不能用高权限服务账号替代用户授权。

3. **读写工具分离：** search/query/get 与 submit/update 分别注册权限；写工具要结构化输入、校验和确认状态。

4. **模型与查询适配：** 封装内网 LLM / embedding、数据库与搜索连接，登记模型、提示词和服务版本。

5. **任务与错误契约：** 长任务返回 job_id，支持幂等、状态查询、有限重试与取消；错误码区分权限/数据/运行问题。

6. **版本与客户端治理：** 接口 Schema、示例、兼容性、调用日志与配额；工具变更有测试和废弃路径。

### 可选能力及触发条件

- **MCP 服务适配：** 当多个 Agent 客户端需要标准工具发现/调用时加 MCP 层，仍复用同一业务授权。
- **技能注册与 Hook：** 可复用技能稳定后登记输入输出/权限/版本；前后置 Hook 做记录与校验，不承诺自动科研推理。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| REST / OpenAPI 业务服务 | 页面和 Agent 共用类型明确的接口，存储实现由适配层隔离。 | 接口与授权薄层需要开发，业务边界清晰。 | 一期建议 |
| MCP 工具入口 | 官方工具规范定义工具 Schema 与调用 [S16]。 | 增加协议、身份和工具治理，MCP 不是权限替代品。 | 多客户端按需 |
| Agent 编排平台适配 | 适配现有框架，使用查询、检索、填报和反馈工具。 | 框架产品能力与模型协议需核查，避免双份业务逻辑。 | 复用已有 Agent |

**推荐：** 先搭统一业务服务并适配现有 Agent。MCP、Skill、Hook 可以后置，业务接口和数据授权先稳定。

### 数据流、记录与验收

业务请求进入网关 → 身份与契约校验 → 调用读 / 写服务 → 适配存储和模型 → 返回标准结果状态 → 关联 Trace 与反馈。

输入：页面/Agent 请求、身份上下文、工具及接口契约。

输出：统一查询/填报结果、任务状态、可追踪错误和调用记录。

关键字段：request_id、principal、project、tool_version、input_schema、job_id、error_code、trace_id。

- 页面和 Agent 对同一业务规则得到一致结果。
- 读工具无法通过注入转成写操作。
- 失败可定位、重试不重复、接口变更有兼容验证。

参考：[S16 MCP Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)；[S07 SQLGlot](https://github.com/tobymao/sqlglot)。

## M10. 平台运维与资产版本

**目标：** 持续运行接入、解析、查询与评测任务，能复现、定位、恢复和回滚。

**项目现状：** 现有脚本覆盖程度待核查，需要建立统一任务和版本管理。

### 一期具体建设内容

1. **任务队列与调度：** 依赖、并发、超时、重试、死信/异常队列和人工重跑，任务状态与资产版本关联。

2. **运行观测与质量：** 记录接入/解析/索引/检索/SQL/模型耗时、错误、积压和资源；质量告警区别基础设施告警。

3. **资产血缘与版本包：** 关联数据、语义层、解析、切分、embedding、索引、Prompt 和模型，运行保存版本清单。

4. **备份与恢复演练：** 备份数据库、原件、元数据、配置和策略；索引可重建，但恢复顺序与耗时需测试。

5. **发布与回滚机制：** 配置和 Prompt 有开发/测试/生产版本；评测通过后切换，保留已知可用版本与回滚依据。

6. **容量与成本归属：** 按查询类型观察 CPU/GPU、模型调用与存储成本；活跃并发、向量规模和保留期驱动扩容。

### 可选能力及触发条件

- **统一观测产品：** 需要 Trace 工作台、Prompt 实验和失败分析时评估 Langfuse/MLflow，明确额外依赖。
- **训练与制品平面：** 开启技能、源码或权重级进化后增加 Git/制品、训练快照、沙箱与评测门禁。

### 业界方式与本项目取舍

| 方案 | 业界能力 | 成本与约束 | 建议 |
|---|---|---|---|
| 轻量任务与版本薄层 | 现有监控＋任务队列，OceanBase 登记任务和版本，原件存储做备份。 | 需要自研一致的任务状态和回滚清单。 | 一期建议 |
| Airflow＋OpenLineage 模式 | DAG 调度 [S18]，Run/Job/Dataset 血缘事件 [S17]。 | 新增服务，实时交互仍由业务服务承担。 | 批流程复杂时 |
| Langfuse / MLflow 主平台 | 观测、评测与资产版本统一管理 [S14][S13]。 | Langfuse 当前官方页面显示 v4，多存储依赖；授权功能按版本核查。 | 明确平台收益后 |

**推荐：** 先做任务状态、版本清单和恢复能力，再按收益引入观测或调度产品。50 用户不等于 50 并发，不据人数直接配置集群。

### 数据流、记录与验收

任务排队与执行 → 关联输入输出版本 → 采集指标与错误 → 评测与发布确认 → 备份 / 失败恢复 → 反馈和容量分析。

输入：任务与查询事件、资产清单、模型配置、备份和评测结果。

输出：监控与告警、版本血缘、恢复记录、发布及回滚证据。

关键字段：job_id、run_id、version_manifest、input_asset_refs、output_refs、release_id、rollback_ref。

- 失败重跑可恢复且不重复产出有效资产。
- 查询能还原当时的数据与配置版本。
- 备份恢复、权限恢复和索引重建都经过演练。

参考：[S17 OpenLineage](https://openlineage.io/docs/spec/examples/)；[S18 Airflow Architecture](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/overview.html)；[S14 Langfuse Self-hosting](https://langfuse.com/self-hosting)；[S13 MLflow Evaluation Datasets](https://mlflow.org/docs/latest/genai/datasets/)；[S22 OpenTelemetry Semantic Conventions](https://opentelemetry.io/docs/concepts/semantic-conventions/)。

| query_run / feedback / audit_event | 输入、结果引用、公开工具调用、版本清单、策略与反馈 | M05/M07/M08 |
| job_run / lineage_event / release_manifest | 输入输出、依赖、重跑、恢复、发布与回滚 | M10 |

原件与索引不强行存为数据库大字段。索引是派生资产，原件、版本元数据和恢复配置必须可恢复；具体物理布局依据 OceanBase 版本、存储产品和负载确定。

统一业务 API 草案：GET /catalog；POST /queries；POST /experiments；POST /imports；GET /jobs/{id}；GET /documents/{id}/versions/{version}；POST /feedback；POST /evaluations。所有入口服务端落实用户/项目/动作授权；写入采用幂等和版本检查。长任务返回 job_id，查询返回 query_id、结果来源、口径、资产版本与配置清单。MCP 是可选协议适配，不重复实现业务规则。

## 14. 统一查询执行顺序

1. 接收身份与项目上下文，判断结构化、文档或混合意图；会改变结果的业务歧义需要在产品流程中澄清。
2. 按访问范围过滤目录，再选候选表族、字段、批准关联和指标口径；不把 3000 张表全部塞给模型。
3. 模型生成 SQL 草案，解析 AST，检查单语句、只读、表列白名单、危险函数、批准关联；服务端强制权限和资源限制。SQLGlot 等解析器不保证授权或业务正确性。
4. 文档路径先按权限筛选，再执行全文与语义检索、重排，证据绑定原件版本和位置。源文档的提示或指令按数据处理。
5. 汇合结构化结果和文档证据，保留冲突、空结果和来源差异，提供可核验摘要。汇总与明细缺关联时明确限制。
6. 保存 query_id、公开工具调用、策略判定、来源引用和版本清单；反馈需专家确认才能成为正式知识或评测资产。

## 15. PoC 与组件选择

选择代表性表族、跨表关联、单位差异、空值、总表/明细冲突，以及文本 PDF、扫描 PDF、复杂表格和 PPT。查询集覆盖单表、聚合、批准关联、混合检索、空答案、越权与写入注入。

检索选型使用实际文档和权限过滤评测：OpenSearch 可提供全文/语义融合及读权限模式；独立向量库可在需要时加入。pgvector 是 PostgreSQL 扩展，现有 OceanBase 环境不等于已经具备其运行基础。数据库的原生向量能力要按安装版本验证。不能按一个统一向量数量阈值替所有产品定结论。

Langfuse/MLflow 的选用由观测、评测和运营收益决定。本轮 Langfuse 官方页面显示 v4，多组件依赖、商业功能与生产配置分别核查；单机 Compose 不等同于高可用和恢复方案。Airflow 用于复杂批处理依赖，页面交互由业务服务承担。

技术验收目标由样本和内部 SLA 确定，不杜撰固定准确率或响应时间。至少要求：越权不能泄漏、禁止写 SQL、结果有依据、修订可追踪、失败可恢复、相同测试版本可复现。正确性、检索召回、证据支持、权限与性能应分项报告。

## 16. 参考材料的采纳与校正

采用用户图片的深色绿色分层工程图、组件连接及控制闭环表现方式。采用参考文档的双数据平面、API/目录/事件三薄层、记忆/档案/评测/治理思想，并展开到本项目十模块。

不把参考文档中的 PostgreSQL 已有、Langfuse 已选定、电站业务或固定向量容量阈值认定为公司事实。保留 OceanBase、公司 AD、内网模型的真实前提。代码进化论文的编码任务结果不能等同于材料研发收益；现阶段不据此承诺自主科学实验。

## 17. 推进顺序与领导决策

A：权限、接入、原件、身份和版本；B：目录、语义、质量和解析索引；C：统一查询、知识和冻结 benchmark；D：恢复、回滚、多团队运营。每阶段以真实验收证据推进。工期和采购由盘点与 PoC 后形成。

领导需要确定一期范围、架构边界、专家与数据负责人的投入，以及跨团队平台责任。平台团队负责服务和运维，数据负责人负责口径/关联，专家负责 benchmark 和确认知识，安全团队负责身份与权限边界，Agent 团队负责工具适配和后续候选评测。

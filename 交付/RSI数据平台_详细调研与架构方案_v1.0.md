# RSI 数据平台调研与架构建议

2026-10-03，v1.0 讨论稿。对象：宁德时代香港研究院锂金属相关材料研发团队。根据项目背景资料更新，面向内部领导确认平台框架与架构。公开来源在正文对应位置列出，事实、建议与待核实项分别标识。

## 一、结论与一期边界

建议一期建设私有化的实验数据填报、资产管理与自然语言统一查询平台，服务约 50 名试点用户。复用现有 Excel/共享盘自动入库脚本和 OceanBase，补齐 PPT/PDF/专家经验的原始资产、元数据、解析索引、检索与权限管理。平台向化学专家提供材料相关信息及证据，后续再引入科研推理、工具技能与模型进化。

已确认一期需要自然语言统一查询 Excel 入库数据和文档，包括生成查询语句或检索摘要。内网已有可用 LLM 和 embedding 服务。结构化路径通过受控 SQL 查询 OceanBase，文档路径采用全文/语义检索并提供来源摘要。普通筛选与搜索作为补充入口和降级方式。

研究背景为锂金属相关材料，一期方案专注数据平台搭建，不扩展化学配套材料内容。已确认 OceanBase 为 MySQL 兼容，约 50 用户，内网模型和 embedding 可用，公司 AD 登录可用。已确认规模为 OceanBase 约 3000 张独立实验明细数据库表，另有少量挂测总表。挂测总表是实验员完成一批电芯的实验后填入汇总结果的表。数据库版本、现有表结构、文件体量与模型服务能力仍需核查。

以下事实来自用户 2026-10-03 的多轮说明，不是系统审计结果。

## 三、公开调研结论与适用范围

1. NOMAD 支持材料数据 Schema 和 ELN，说明结构化材料对象与文档管理可以共用语义模型。[官方文档](https://docs.nomad-lab.eu/)，[ELN 文档](https://docs.nomad-lab.eu/howto/manage/gui/eln.html)。本项目可借鉴其字段与解析方式，不直接替换 OceanBase。
2. AiiDA 关注工作流与来源追踪，可借鉴输入、过程、结果的关联模型。[论文](https://arxiv.org/abs/2003.12476)。一期用文件、样品、结果与导入批次的标识关联即可，仿真链路按实际需求扩展。
3. AIMD-L 使用事件数据层关联多仪器数据与样品历史。[机构说明](https://hemi.jhu.edu/caimee/center-facilities/aimd-l/data-handling/)。这是后期自动实验的参考，当前不要求引入仪器控制或复杂消息基础设施。
4. Reflexion 使用反馈和情景记忆支持后续尝试。[论文](https://arxiv.org/abs/2303.11366)。EvoDS 展示可执行技能学习与验证。[论文](https://arxiv.org/abs/2606.03841)。EvoMaster v5 强调跨实验和研究保留证据。[论文](https://arxiv.org/abs/2604.17406v5)。这些研究支持未来记忆、技能与证据资产设计，不能证明公司材料研发已有可量化收益。
5. MLflow 支持从运行记录创建评测数据集与过程评测。[评测数据集](https://mlflow.org/docs/latest/genai/datasets/)，[执行记录评测](https://www.mlflow.org/docs/latest/genai/eval-monitor/running-evaluation/traces/)。可用于比较版本，材料科学指标仍需专家定义。
6. NIST 将样品、通信、数据知识和模型集成列为自主实验生态的标准化方向。[机构说明](https://www.nist.gov/programs-projects/development-standards-support-modular-and-autonomous-laboratory-ecosystem)。平台接口应分层设计，当前资料并不说明全行业已有统一标准。

调研方式：摘要、研究机构说明与官方文档的定向调研，尚未完成源码适配或产品 PoC。没有将论文基准提升率当作本项目 ROI。

## 五、建议架构与组件责任

逻辑分层：

- 入口：化学专家查询页面、数据管理员页面、已有 RSI Agent 接口。
- 数据服务：身份校验、项目授权、结构化查询、文档检索、来源定位、下载、反馈。
- 接入处理：已有 Excel 脚本适配、共享盘扫描/上传、文件登记、内网解析、单位与术语映射、质检、索引任务。
- 持久资产：现有 OceanBase 保存科学业务数据；建议同产品隔离库/租户保存文档元数据与管理状态，MySQL 兼容已确认，版本及权限配置待核实；私有对象存储保存原始文件和解析产物；搜索索引保存全文与可选向量。
- 横向管理：用户/服务身份、项目权限、审计、版本、备份、处理队列、失败重试和监控。
- 内网模型服务：embedding 支持语义检索，LLM 支持查询意图、SQL 生成和检索摘要。内网模型服务已确认存在，仍保留普通查询和全文搜索的降级入口。

事实权威来源：科学业务值以治理后的 OceanBase 表为准；原始证据以文件版本为准；元数据目录记录关联和权限；检索索引是可重建派生数据。禁止把检索索引当作唯一原始资产。

对象存储候选应符合私有化部署与公司软件政策，也可先采用受管理的文件服务加存储引用。搜索服务候选可评估 OpenSearch 或已有同类能力，不提前锁定采购。OpenSearch 官方文档支持混合检索与文档权限能力，但兼容性、运维及授权规则均需要 PoC。[混合检索](https://docs.opensearch.org/latest/vector-search/ai-search/hybrid-search/index/)，[文档权限](https://docs.opensearch.org/latest/security/access-control/document-level-security/)。

OceanBase 官方文档区分 MySQL 和 Oracle 兼容模式，现有环境已确认 MySQL 兼容，具体版本及兼容能力需核实后确定驱动和元数据方案。[兼容模式](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000005283144)。

## 六、主要数据流

### 结构化接入

Excel/共享盘登记导入批次，校验字段及单位，既有脚本通过受限写入身份更新 OceanBase。保存原始 Excel 引用、记录数、失败原因和处理版本。幂等键避免同批次重复写入，失败批次可重试。具体由现有脚本补齐还是平台接管调度，待现状核查决定。

### 文档接入

扫描/上传共享盘文件，生成标识、校验值和版本，保存原件到私有存储，并登记元数据。内网解析生成文本、表格、图片说明与页/幻灯片位置。必要时 OCR。质检后切分、建立全文索引，内网 embedding 可用时生成向量。解析失败进入处理队列，禁止静默标记为可用。

### 查询

化学专家提交条件或关键词，服务端进行身份与项目授权。结构化查询调用只读视图，文档检索在授权范围内查询索引。展示材料/样品记录、相关文档和来源位置，支持原件查看和受控下载。跨结构化与文档的关联依靠实体标识和元数据，关联缺失时分别展示，避免伪造匹配。

如果启用摘要，摘要仅引用本次已授权证据。权限过滤应在检索前及结果返回前校验，并覆盖原件下载、缓存和派生摘要。一期自然语言 SQL 需要查询白名单、参数化、只读凭据、行数/时间限制和测试集验证。

### 更新和撤回

文件新版本触发解析与重建索引，查询记录保存当时版本。撤回或权限变化触发元数据更新、检索过滤与索引/缓存同步失效。以受限状态隔离尚未完成同步的资产，避免窗口期继续对外返回。

## 七、专家访谈和 benchmark 的分别管理

一次访谈可以产生两类资产。知识资产包括原始记录、专家经验卡、支持案例和适用条件，用于日常检索。评测资产包括问题、预期答案、证据位置、评分准则及数据版本，用于独立检验检索与建议质量。

专家确认经验的适用边界、证据及反例。benchmark 的评分答案不进入面向 Agent 的在线检索库。评测所需业务文档可以按任务设计允许检索，但隐藏答案、评分规则和测试反馈必须隔离。训练/开发集与独立测试集按任务、项目或时间划分，并对同一实验的近重复文档做关联检查。

一期 benchmark 优先覆盖：结构化条件查询、文档检索、关键事实与测试条件抽取、引用位置正确性、无证据问题、权限拒绝与过期版本处理。科研推理 benchmark 在二期进一步定义。

## 八、私有化部署与权限最小方案

所有生产数据处理组件部署在内网，不依赖云端文档解析、embedding 或大模型。浏览器访问业务服务，业务服务访问数据库、存储和搜索服务。管理员通过单独运维入口执行维护。具体网络分区、节点数和高可用方案按公司标准和规模确定，当前不承诺物理部署拓扑。

最小身份方案：对接公司 AD 或批准的 SSO，映射化学专家/数据管理员/平台管理员角色、项目授权和服务账号。身份认证与数据授权分别管理，不另建重复身份体系。密码策略、内部 TLS/证书、日志保留期及备份策略由内部安全要求决定。AD/SSO 具体协议、组和项目映射待内部核实。权限必须贯穿目录、查询、源文件、索引及 Agent，不能只在页面隐藏数据。

依赖包、解析器与模型权重通过公司批准的流程进入内网。备份同时覆盖 OceanBase、原始存储、元数据与配置，检索索引可重建但必须验证重建耗时。香港与内地访问路径及边界待公司相关团队确认，本文不作法规结论。

## 九、阶段计划与验收

阶段 A：数据与查询基线。选取真实查询任务，核查 OceanBase 表、数据体量和现有脚本，确认元数据字段与权限规则。

阶段 B：团队试点。建设文件登记、原件管理、内网解析、全文搜索、结构化查询、来源定位和最小权限。采集专家反馈，建立独立查询 benchmark。

阶段 C：自然语言统一查询。建设 Schema 检索、受控 SQL、语义检索、来源摘要、Agent 对接及专家 benchmark。验收后再讨论科研推理和技能/模型进化。

阶段 D：公司级与自进化。多团队领域扩展，增加数据运营、技能验证、训练数据管理、策略与模型评测发布。依赖稳定实验反馈及明确责任人。

验收建议：目标数据集导入完整率、解析成功率及关键字段正确率、材料/样品关联率、查询正确性、证据引用位置准确性、授权访问与撤回用例、失败可恢复、备份可恢复、查询时延及专家任务完成时间。具体目标值由规模和现状基线决定，不编造准确率或提速承诺。

## 十、领导需确认的事项与未决参数

建议领导确认一期目标、现有资产复用原则、原始文件/元数据/索引的职责分工、权限及运维责任、查询 benchmark 的专家投入，以及通过试点验收后再扩大范围的路径。

待补充：OceanBase 版本与表结构、批次/电芯与明细/汇总的关联字段、文档体量、内网模型具体接口与性能、AD/SSO 协议、现有录入和知识库接口、PPT 品牌模板。用户已确认约 50 用户、MySQL 兼容、公司 AD、内网模型、自然语言统一查询、一期填报和 45 分钟汇报。上述问题不会阻止逻辑架构讨论，但影响物理部署、实现工作量和排期。

## 十一、大规模实验表与业务语义层

平台需要管理表目录，登记表及字段释义、业务主题、数据负责人、项目权限、时间范围、更新状态、质量规则及可用关联键。再建立语义层，统一用户术语、指标口径、单位、时间字段及获准查询视图。已确认约 3000 张独立数据库表，目录需要覆盖多物理表及其业务口径，而不仅是 Excel 文件管理。

模型不应一次接收全部表结构。查询先根据项目权限和主题缩小范围，再检索候选表/字段，仅把必要 Schema 和批准关联送入生成环节。若存在一实验一表，先通过目录与只读视图治理，后续评估按实验类型统一明细模型，不承诺一期迁移所有历史表。统一查询不是一次查询全部表，而是从自然语言问题选择适合的数据域和来源。

语义条目需要版本、审批人和生效状态。聚合口径和总表是否可与明细对齐由数据负责人确认，避免不同口径产生看似一致的结果。

## 十二、实验填报的产品与接口要求

一期包含填报页面。建议对接既有录入雏形，先核查页面与接口可复用程度，再决定由谁提供界面与后端。模板应包含实验/样品/项目标识、字段类型、必填项、单位、允许范围和附件规则，并随业务变化保存版本。

状态可采用草稿、已提交、复核中（按业务要求启用）、已入库、退回、作废。普通格式校验自动执行，科学异常先提示或进入复核，不一律拒绝。记录修订保留旧值、原因、操作者和时间。重复提交用幂等键防重，并发修改用版本检查提示冲突，重要写入在事务中完成。

批量导入提供预检查、逐行错误和结果报告，保存源文件和批次。已有 Excel 脚本与填报接口使用统一字段契约，避免两条链路出现不同单位或标识定义。查询服务只读，填报服务以受限写入身份执行，模型不能直接操作生产写入凭据。

## 十三、自然语言 SQL 详细设计

1. 将用户问题转为任务意图，识别结构化、文档或混合查询。材料、时间和指标含义存在会改变结果的歧义时先澄清。
2. 服务端根据身份和项目筛选目录，再检索相关表、字段和关联。语义定义与 SQL 模板必须来自已发布版本。
3. 模型生成查询草案。AST/解析器检查语句类型、表和列白名单，禁止多语句、写入、DDL、越权关联及危险函数。
4. 服务端强制数据授权，使用只读身份、获准视图/过滤策略，限制查询行数、执行时长、导出体量及昂贵查询。具体行级策略与 OceanBase 版本、Schema 设计共同核实。
5. 失败时只允许有限次数修正，保留诊断与版本。无法确认关联关系时提示限制，不能任意构造连接。
6. 返回表格、口径、关键筛选条件、来源/数据时间和可查看的 SQL 解释。自然语言摘要基于结果生成，SQL 执行成功仍需 benchmark 检查语义正确性。

评测覆盖单表筛选、聚合、多表关联、单位和时间处理、口径歧义、空结果、无适合数据源、越权、恶意写入、昂贵查询和过期 Schema。按代表性业务任务分层，样本数与指标目标由专家共同确定。

## 十四、接口契约草案

接口路径仅为实施讨论示例，不代表已上线接口。GET /catalog 查询可访问目录；POST /query 接收问题、上下文和项目，返回结构化结果、文档证据、解释和 query_id；GET /documents/{id}/versions/{version} 受控获取原件；POST /experiments 提交校验后的记录；POST /imports 创建导入批次；GET /jobs/{id} 查看处理状态；POST /feedback 关联 query_id 和纠正信息。

共同字段包括用户/服务身份、项目、资产版本、request_id、状态与错误码。查询响应包括数据来源、文档页位置、使用模型/提示词/语义层版本、执行耗时与权限范围。所有长任务提供可查询状态和幂等策略。凭据不能放在模型上下文或客户端代码中。

## 十五、PoC 与实施责任

PoC 选择代表性实验类型和文档格式，覆盖普通数据、异常、扫描件、复杂表格、重复版本和权限差异。核验真实查询结果与原件证据，不用演示页面代替数据正确性。并发和容量测试按约 50 用户的实际活跃分布设置，人数不等于并发数，当前不据人数直接指定机器配置。

建议责任：数据平台负责接入、目录、授权数据服务、任务运维和资产管理；数据负责人确认字段、指标及质量规则；化学专家标注查询案例和经验边界；Agent 团队负责现有接口和后续推理编排；基础设施/安全团队负责 AD 接入、模型服务、网络、证书与恢复标准。具体组织归属由内部确认。

交付顺序：数据与接口核查、代表性 PoC、基础资产与填报、自然语言查询、评测与权限验收、试点稳定运行。阶段通过条件明确后再确定排期和预算。


## 十六、挂测总表与实验明细的关联治理

已确认挂测总表由实验员在完成一批电芯实验后填写汇总结果。建议将电芯批次、单电芯（如存在标识）、实验、明细测量和汇总记录分别建模或在目录中映射。需要明确汇总覆盖的电芯范围、实验阶段、时间、统计口径、排除规则、填写者和版本。总表中的人工判断与可计算统计值分别标识。

SQL 查询不得将汇总值再与原始明细相加。需要判断用户要的是单电芯/测量明细还是批次汇总。可计算的汇总字段可以与相同条件下的明细核对，无法从现有数据推导的指标保留人工填写来源与解释。明细修订时，标记对应汇总可能过期，再按规则重算或请实验员重新确认。暂不假定汇总指标一定为均值、最大值或其他具体公式。

典型流程示例（非现有系统事实）：实验员选择批次 B，填写实验 E 的汇总记录，关联明细与附件；专家提出“查询批次 B 的实验 E 汇总结果，列出对应明细，并给出相关报告证据”；服务按授权选择相应视图和文档，分别展示汇总、明细、统计口径、文档位置和版本。如果缺少关联键或结果冲突，明确说明限制。该示例可作为一期 benchmark 种子，使用真实字段校准后纳入正式评测。

## 十七、45 分钟汇报使用建议

配套 PPT 为 30 页，其中前 27 页为主体与业务场景，后 3 页为功能、字段和来源附录。建议目标与现状约 7 分钟，架构/目录/接入/查询约 18 分钟，填报/权限/质量/实施验收约 10 分钟，扩展与领导决策约 5 分钟，保留约 5 分钟讨论。时间仅为讲述安排建议，不是开发周期。
